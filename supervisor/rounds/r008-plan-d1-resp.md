**3. 被抓到的流程（含 jump scare 開與關）**

建議由 `chapter` 消費**本幀新產生的** `contact`，底層 `updateMonster` 繼續只負責接觸事件、碰撞與遲滯。

流程：

`explore → caught → 回復存檔點 → explore`

建議初始時間如下，開關兩種流程總長相同：

| 被抓後時間 | `jumpScare=false` | `jumpScare=true` |
|---|---|---|
| 0～0.15 秒 | 黑畫面 | 黑畫面 |
| 0.15～0.50 秒 | 維持黑畫面 | 原創棉花糖先生近景突然出現，短暫放大 |
| 0.50～1.20 秒 | 維持黑畫面 | 回到黑畫面 |
| 滿 1.20 秒 | 回復存檔點 | 回復存檔點 |

視覺實作選項：

| 選項 | 評估 |
|---|---|
| 把場景內怪物移到相機前 | 沿用模型，但要額外保存、還原場景變換 |
| **獨立 Canvas 2D 幾何近景，建議** | 糖塊臉、紙帶帽、圓扣眼與短手臂；容易隔離開關，不新增 three.js 光源 |
| 獨立 three.js 展示場景 | 輪廓最一致，但增加渲染與資源管理 |

建議採第二種：只做單次突然出現與放大，不加尖牙、血、閃爍、音效或連續震動。Canvas 畫一次，顯示進度由 logic 驅動。

被抓期間：

- 禁止移動、轉頭、互動、裝備與密碼鎖命令。
- 怪物、耗電與一般場景更新停止，只推進被抓計時。
- Esc／Start／Options、失焦、拔除手把仍可暫停；暫停時隱藏嚇人近景，保留黑底。
- 計時採有效 `dt`、單幀上限 `0.1` 秒，不使用 `setTimeout`。
- 開始、結束當幀清除待處理輸入，不重播互動或裝備按鍵。

**4. 存檔點位置與觸發**

建議「最近」指**最後啟用的進度存檔點**，依大廳→電力室→生產線前進；回頭走不降級。

所有位置眼高均為 `1.6 m`、`pitch=0`。

| ID | 回復位置與朝向 | 啟用條件 |
|---|---|---|
| `lobby.checkpoint` | `(0,6)`，朝北 `yaw=0` | 確認開始新遊戲 |
| `power.checkpoint` | `(0,-1.2)`，朝北 `yaw=0` | 持有手電筒，首次完整進入電力室 |
| `production.checkpoint` | 平台 `(6.5,-6.5)`，朝東 `yaw=-π/2` | 主電力恢復，首次完整進入生產線 |

「完整進入」以玩家中心位於區域內縮 `PLAYER_RADIUS` 的範圍判斷，避免在門界來回觸發。

恢復供電會立即保存解題進度，但**尚未走進生產線時，不提前啟用生產線存檔點**。

生產線回復位置有兩個主要選項：

- 區內入口＋短暫無敵：需要額外處理保護結束與怪物堵門。
- **平台安全點，建議採用**：利用已採認的怪物活動邊界，無須增加無敵時間。

本回已用正式幾何核對三個候選位置均無玩家碰撞；平台點距怪物初始位置約 `12.59 m`，且在其活動區外。生產線存檔點資料可放在 `production.js`，但回復位置明確引用平台地板，不要求落在生產線區域 bounds 內。

**5. 回到存檔點時逐項保留／重置表**

死亡回復與讀檔共用同一套重建規則；死亡使用當下進度，讀檔使用最後成功寫入的進度。

| 項目 | 處理 | 理由 |
|---|---|---|
| 已取得物品 ID | 保留最新集合 | 手電筒、保險絲及已消耗電池都不能重新出現 |
| 保險絲安裝狀態 | 保留 | 不重做已完成操作 |
| 已解謎題 | 保留 | 符合 VERIFY |
| 門狀態 | 從保留進度重新推導 | 不另外保存門旗標，避免門與碰撞不一致 |
| 手電筒電量 | 保留最新電量，不補電 | 不因死亡或讀檔免費充電 |
| 手電筒模式 | 保留 | 避免無必要的操作重設 |
| 手電筒開關 | 關閉 | 不在黑畫面／重生時繼續耗電 |
| 玩家位置與視角 | 固定存檔點資料 | 不存危險位置或櫃內座標 |
| 櫃子、密碼鎖介面 | 清除，回探索 | 不殘留鎖定視角或半套輸入 |
| 怪物位置與巡邏進度 | 回正式出生點 B | 避免怪物守在重生點 |
| 怪物追逐記憶、路徑、接觸遲滯及事件 | 清除 | 防止立即重抓或重播舊事件 |
| 怪物是否啟動 | 未到生產線為 `inactive`；已到則從 B 恢復 `patrol` | 不讓讀檔永久停用怪物 |
| 供電轉換動畫 | 已恢復者直接為完成狀態 | 不重播亮燈動畫 |
| 暫停與裝置狀態 | 不持久化 | 讀檔先停在開始畫面，由玩家確認繼續 |
| jump scare 偏好 | 從外部 options 取得 | 與 S2 設定獨立 |

怪物重置只發生在**死亡回復或讀檔**；普通離區、再進區仍維持 STEP 5 的不重置規則。沒有永久或計時無敵，重新進區後照正常視線與接觸規則仍可再次被抓。

**6. 瀏覽器存檔設計**

儲存方式比較：

| 方式 | 評估 |
|---|---|
| 整包 chapter JSON | 包含介面、路徑與危險座標，版本容易失效 |
| 存檔點當時的完整快照 | 可能丟失之後取得的物品，不符合本步要求 |
| **最新必要進度＋固定存檔點 ID，建議** | 保留最新成果，回復位置可安全重建 |

建議單一章節存檔槽，key 為 `star-candy-park.chapter-1.save`；版本號放在內容：

```json
{
  "version": 1,
  "chapterId": "chapter-1",
  "checkpointId": "production.checkpoint",
  "itemIds": ["lobby.flashlight", "power.fuse"],
  "puzzles": {
    "power.main": {
      "installedItemId": "power.fuse",
      "restored": true
    }
  },
  "flashlight": {
    "charge": 82.5,
    "mode": "normal"
  }
}
```

不存玩家即時位置、怪物、介面、輸入、計時器、設定、密碼副本或預留謎題的未實作進度；本步不新增結局用遊玩計時。

驗證與失敗處理：

- 嚴格檢查版本、型別、已知 ID、電量範圍及進度前置條件。
- 例如生產線存檔點必須具備已恢復供電及必要取得／安裝紀錄。
- 壞 JSON、不支援版本或矛盾資料：不套用、不崩潰；顯示無法繼續的原因。
- 不默默刪除或覆寫問題存檔；玩家確認新遊戲後才取代。
- 第一版沒有既有正式格式可遷移；未來版本需另定遷移，不猜測轉換。
- 儲存存取失敗時維持遊戲與記憶體進度，明確提示尚未儲存。

寫入時機：

- 新遊戲確認、首次啟用存檔點、取得物品、安裝保險絲、解題成功、死亡回復：立即寫入。
- 單純耗電：有變更才寫，最多每 5 秒一次。
- 暫停、`visibilitychange` 轉背景、`pagehide`：補寫待存進度。
- 不依賴關頁事件才保存取得／解題成果，不逐幀 `JSON.stringify` 或存取 localStorage。
- 先完成序列化，再呼叫單次 `setItem`；不先刪掉舊檔。

開始畫面建議有「繼續」與「重新開始」：有效存檔時預選繼續；重新開始需確認，且只替換章節 key，不呼叫 `localStorage.clear()`。鍵鼠與手把皆可選取、確認、取消。

Node 透過注入 `{getItem,setItem,removeItem}` 的假儲存測試，另模擬讀寫拋錯；logic 不直接碰 `window.localStorage`。

**7. 怪狀態的處理**

| 情境 | 建議規則 |
|---|---|
| 成功進櫃與接觸同幀 | 維持既有進櫃優先、消耗當幀；成功躲藏後不被抓 |
| 櫃內 | 不產生新接觸；舊事件不能觸發被抓 |
| 密碼鎖開啟、取消或提交當幀 | 維持原有 AI 凍結，不補算接觸 |
| 暫停、失焦、拔除 | 先處理中斷，不推進被抓或 AI |
| 被抓期間再次出現事件 | 不重開流程、不重設計時 |
| 手電筒開著被抓 | 當幀關閉，其後停止耗電 |
| 櫃內／面板／被抓途中關頁 | 只存進度；繼續時回固定存檔點，不還原瞬間模式 |
| 剛回復 | 清除事件、介面與待處理輸入；回復當幀不再跑 AI |
| 讀檔後立即被發現 | 平台位置與怪物 B 起點分開，不需無敵 |
| 同頁重新開始 | 物品模型依新背包重新顯示；不能沿用目前「撿取後刪除模型」而漏掉物品 |

當幀已成功完成的取得／解題不回滾；進入被抓模式後不再接受其他場景命令。
