2. **「看著」的判斷做法（選項與建議）**

| 選項 | 做法 | 取捨 |
|---|---|---|
| A：中央射線命中物品方塊 | 從眼睛沿視線射出射線，命中物品 AABB 才算 | 準星與判定一致，純數學即可測試；小物品需瞄準 |
| B：物品中心在視線角度內 | 比較視線與物品中心方向，例如夾角不超過 5° | 容易瞄準，但準星未碰到模型也可能出現提示 |
| C：射線命中放大的互動範圍 | 模型外另給較大的命中方塊 | 較寬容，但畫面與判定範圍不同，資料也較多 |

**建議 A**：本步示範物品直接用可辨識大小的方塊，模型與判定共用同一組 AABB。

眼睛位置採 `{ x: player.x, y: EYE_HEIGHT, z: player.z }`，方向由現有 `yaw／pitch` 推導，與相機一致。建議將「2 公尺」明定為**眼睛到射線首次碰到物品表面的距離，含恰好 2 公尺**。多個物品重疊時只選最近的一個。

3. **隔牆判斷的做法**

在 logic 實作三軸區間交集的射線／AABB 判斷，不使用 three.js：

- 算出最近未撿物品的命中距離。
- 同一條射線檢查 `LEVEL_BOXES` 的全部方塊，以及 `ROOM_SURFACES`。
- 障礙物比物品更近或同距離時，不能撿；障礙物在物品後方不影響。
- 使用完整 XYZ，確保桌面上的物品不會因桌子位於其下方而被誤擋。
- 提示與按下互動時均呼叫同一個選取函式；按鍵當幀重新判定。

測試房間新增可繞行的短隔板。使用 `kind: 'partition'`，納入既有碰撞清單，畫面套用牆壁材質。既有測試要求四個 `kind: 'wall'`，因此保留四面外牆的定義。

4. **物品與背包的資料形狀**

唯一物品清單放在 `src/logic/items.js`，例如：

```js
{
  id: 'demo-table-token',
  name: '測試代幣',
  minX, maxX,
  minY, maxY,
  minZ, maxZ,
  color: 0xffcc66
}
```

game 用相同 AABB 建立方塊模型，logic 用它選取，不另存第二份位置或尺寸。

背包採：

```js
{ itemIds: [] }
```

撿取函式回傳新狀態，不修改物品定義；已在背包的 ID 不再參與選取。game 以 ID 對應模型並移除。暫不做容量、堆疊、丟棄或存檔。

放三個示範物品：桌上、開放區、隔板後方；隔板後的物品可繞過隔板取得。

輸入沿用既有 `readGamepad／mergeActions`，增加共用 `interactPressed`：

- E：僅首次按下觸發，忽略自動重複。
- A／✕：沿用按鈕 0 的按下邊緣。
- 提示使用 `buttonLabel('interact', prompt.device)`，保留現有 0.5 秒切換規則。
- 開始／繼續當幀消耗選單操作，避免同一次 A／✕ 順便撿物品。
- 暫停、失焦時忽略並清除待處理互動。
