1. **目標**

   完成 `PLANS.md` 的 **STEP 1「第一人稱移動」**，通過 `VERIFY.md` STEP 1 的全部條目：

   - 點畫面後鎖定滑鼠，移動滑鼠可轉頭。
   - 按 W、A、S、D 可前後左右移動。
   - 按 Esc 解鎖滑鼠並顯示暫停畫面。
   - 不能穿過牆壁或桌子。
   - 視角不能上下超過 90 度而翻轉。

   這一步不實作手把，但輸入會先轉成裝置無關、可表達類比值的動作，再交給 logic。手把接入與搖桿死區留在 STEP 1b。

2. **「動作」的形狀**

   建議由 game 每幀交給 logic 一個動作物件：

   - `move.x`、`move.y`：`-1` 到 `1`，表示左右與前後；按鍵組合先正規化，避免斜向移動更快。這個範圍可容納搖桿類比值。
   - `look.yawRate`、`look.pitchRate`：`-1` 到 `1`，表示水平與垂直轉頭方向及幅度。game 將 Pointer Lock 滑鼠位移依靈敏度換成角速度，再交給 logic；未來手把可直接把右搖桿軸值轉成相同欄位。
   - `pausePressed`：布林值，表示本幀是否觸發暫停。
   - `dt`：由 logic 更新函式接收，單位秒；限制最大值，避免切回分頁時的大時間差讓角色瞬移。

   logic 只讀取這些動作數值，不辨識按鍵或裝置。logic 負責套用移動速度、角速度、視角上下限與碰撞；game 負責按鍵及滑鼠事件、Pointer Lock 和暫停畫面。

3. **碰撞做法**

   - **選項 A：玩家水平圓形範圍對 AABB 方塊**。玩家仍視為有高度的圓柱，但碰撞在地面平面做圓與方塊測試。每次移動分軸解析或小步進，適合目前沒有跳躍的玩法。**建議採用此選項**：能在 Node 測試，成本低，也比方形玩家碰撞更貼近圓柱形玩家。
   - **選項 B：玩家水平方形範圍對 AABB 方塊**。最簡單，但角色會在家具角落提早卡住，手感較生硬。
   - **選項 C：完整 3D 圓柱對 AABB**。形狀描述最精確，但目前固定高度且沒有跳躍，實作與測試成本較高。

   建議 A 使用圓與方塊的最近點判斷，沿 X、Z 軸分開移動與解析；必要時依移動距離切成小步，避免高速移動穿過薄障礙。房間牆壁與桌子都以 AABB 表示。

4. **檔案白名單**

   - `src/logic/movement.js` — 接收移動動作與 `dt`，處理速度、視角角度限制及玩家圓柱對方塊的碰撞。
   - `src/logic/index.js` — 匯出移動 logic，保留 logic 不匯入 three.js 的邊界。
   - `src/game/main.js` — 加入桌子等障礙物、鍵盤滑鼠輸入轉換、Pointer Lock、暫停畫面及 logic 更新與渲染的連接。
   - `tests/movement.test.js` — 測移動、視角限制、碰撞與 `dt` 行為。
   - `PLANS.md` — STEP 1 驗收完成後打勾。

5. **驗收**

   **先紅後綠的測試名稱建議：**

   - `使用移動動作時會依 dt 與速度更新位置`
   - `斜向移動不會比單方向移動更快`
   - `look 角速度會依 dt 更新視角`
