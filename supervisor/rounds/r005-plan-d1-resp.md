2. **電量數值與理由**

| 項目 | 建議值 |
|---|---|
| 起始狀態 | 100%、關閉、一般光 |
| 耗電速度 | 每秒 0.2 個百分點；兩種模式相同 |
| 每顆電池 | 補充 25 個百分點，上限 100% |
| 用盡 | 電量停在 0，自動關閉；補電後需自行開啟 |

滿電可連續使用 **8 分 20 秒**，每顆電池增加 **2 分 5 秒**。以一章 15～20 分鐘、約六至七成時間開燈估算，需要約 1～3 顆有效補充；足以鼓勵關燈節省，也保留探索餘裕。

本步放兩顆示範電池；正式章節的數量與位置留待 STEP 4 及後續關卡安排，尚不能保證整章不會卡關。

補充規則：

- 關閉、暫停、失焦時不耗電；開始／繼續當幀不計耗電。
- 關閉時也能切換模式，但不因此開燈。
- 滿電仍可撿電池，超過上限的部分捨棄；本步不新增儲存電池或手動使用功能。
- logic 使用有效的非負秒數計算，不依畫格數耗電；負數或非有限時間視為 0。

3. **「照得到」的判斷做法**

| 選項 | 做法 | 取捨 |
|---|---|---|
| A：隱藏字中心在光錐內 | 中心通過距離、角度、正面與遮擋檢查，整段字顯示 | 簡單、穩定、容易測試 |
| B：中心與四角取樣 | 多個取樣點通過才顯示 | 可處理部分遮擋，但門檻較難理解 |
| C：中央射線命中字牌 | 必須用準星直接瞄準字牌 | 判定精確，但比實際光束窄，手把較難操作 |

**建議 A**，本步只放一小段文字，採整段顯示／隱藏。

建議共用光束設定：**半角 25°、有效距離 8 m**，邊界包含在內。logic 判斷以下條件全部成立才可見：

- 手電筒開啟且電量大於 0。
- 模式為紫外光。
- 文字中心在距離與光錐角度內。
- 玩家位於文字正面。
- 眼睛到文字中心之間，沒有 `LEVEL_BOXES` 或 `ROOM_SURFACES` 遮擋；障礙物同距離也算遮擋。

沿用 `viewRay` 與 `rayBoxDistance`，但遮擋射線改朝文字中心，不套用撿取的 2 m 限制。文字平面放在牆面外側 0.02 m，判定與模型使用相同位置，不略過整面附著牆。

game 使用同一份角度、距離設定建立 SpotLight；一般光偏暖白、紫外光明顯偏紫。**不開陰影、不加後製**。因此光照效果可能穿過隔板，但隱藏字可見性仍由 logic 遮擋檢查決定，不會隔牆顯示。

4. **隱藏字與電池的資料形狀**

手電筒狀態：

```js
{ charge: 100, enabled: false, mode: 'normal' }
```

隱藏字唯一資料放在 `src/logic/clues.js`：

```js
{
  id: 'demo-uv-text',
  text: '星光在此',
  position: { x: 2.5, y: 1.6, z: -0.02 },
  normal: { x: 0, y: 0, z: -1 },
  width: 1,
  height: 0.35
}
```

放在隔板背面，方便驗證繞行、正反面及遮擋。game 從相同位置與法向量建立文字平面，以程式產生文字材質；只依 logic 結果設定可見性。

電池沿用 `items.js` 的物品資料，增加：

```js
{
  // 保留既有 id、AABB 與顏色欄位
  kind: 'battery',
  chargeAmount: 25
}
```

**將桌上代幣、藍色代幣改為示範電池，保留原 ID 與 AABB**；隔板後代幣保留。如此仍有三件物品，符合既有測試的固定數量，所有物品三邊仍至少 0.25 m。

logic 中的裝備更新函式呼叫既有 `collectItem`，比較撿取前後的 `itemIds`，只對本幀新增的電池 ID 補電，再由 game 移除模型。沒有第二套撿取判定，也不會每幀重複補電。
