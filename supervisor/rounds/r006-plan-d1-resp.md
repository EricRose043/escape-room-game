5. **謎題設計**

建議四位固定密碼 **`4726`**，本步不做隨機碼或額外排列謎題。

流程：

1. 撿到手電筒，大廳門自動開啟；未持有時不能開燈，也不能離開。
2. 在工作桌取得保險絲。
3. 瞄準電箱，在 2 m 內按 E／A／✕ 安裝；使用共用射線選取與遮擋規則。
4. 電箱亮一個低亮度指示燈，顯示「備援控制已接通」；房間主燈仍未恢復。
5. 使用紫外光找到「檢修碼：4726」。
6. 對密碼鎖互動，輸入正確碼；主燈恢復、生產線門開啟。

提示方式：

- 服務台標示「雙光源巡檢燈」，配簡單紫色檢修符號。
- 電箱旁的維修便條寫「檢修墨跡在普通照明下不可見」。
- UI 保留依裝置變化的切換光線按鍵提示。
- 不在一般光下顯示密碼，也不直接彈窗告訴玩家答案。

無保險絲時，電箱回饋「缺少保險絲」；未插入時密碼鎖只回饋「控制器未通電」，**不開輸入介面，logic 也拒絕直接提交**。錯碼顯示錯誤、清空輸入，不扣除物品、不恢復供電。

6. **密碼鎖介面的狀態與操作**

**介面狀態放 logic，DOM、焦點與 Pointer Lock 操作放 game。**

```js
{
  mode: 'keypad',
  deviceId: 'power.keypad',
  buffer: '',
  selectedIndex: 0,
  message: ''
}
```

採 3 × 4 按鍵：

```text
1   2   3
4   5   6
7   8   9
刪除 0  確認
```

- 滑鼠點按鍵；鍵盤數字、Backspace、Enter 也映射成相同命令。
- 手把十字鍵移動選取框，A／✕ 啟用所選鍵，B／○ 返回探索。
- 十字鍵只認按下邊緣，邊界不循環；輸入最多四位。
- 畫面有獨立「返回」按鈕；每次重新開啟清空舊輸入。
- 開啟、關閉當幀消耗操作，避免開鎖的 A／✕ 同時輸入第一位數字或再次互動。

介面開啟時停止移動、轉頭、場景互動與裝備動作；建議同時凍結耗電。暫停、失焦或拔手把仍可進入暫停；回來保留輸入內容，但不重播按鍵。

鍵鼠開啟介面時，以明確的「開啟密碼鎖」原因釋放 Pointer Lock，不能因此觸發暫停。Esc 在介面內優先返回；鍵鼠返回後可由實際點擊重新鎖定，失敗則沿用現有提示。純手把流程完全不要求 Pointer Lock。

7. **氣氛與效能做法**

氣氛採靜態細節：褪色星星招牌、關閉的服務台、空工具架、維修便條與昏暗走道。維持可辨識的底光，不做音效、怪物或突然跳出的畫面。

恢復電力時採一次短暫的「低亮度啟動→穩定亮起」，約 0.6 秒，不做反覆快速閃爍。進度由 logic 的供電轉換時間決定，game 顯示燈光。

效能：

- 最多一盞 SpotLight、兩盞啟用的房間 PointLight，加一盞 AmbientLight。
- 電箱指示燈用發光材質，不另增真實光源。
- 不開陰影、不加後製；沿用像素比上限 1。
- 幾何、材質與文字貼圖建立一次；狀態變更時更新，不逐幀重建。
- 房間燈由目前／相鄰區域選取，未來加區不隨區域總數增加啟用光源。

兩個小修放在 **4a**：

- 近距過曝：加入近距光強補償，中央射線最近表面在 1 m 內時按距離平方降低光強，上限維持正常值；不改耗電、光錐及紫外光判斷。效果交監督者比較近、中、遠距物品。
- 重複百分比：現有 HTML 同時有 `<meter>` 內文字與旁邊的百分比；移除重複字串，保留一份可見數值及適當的無障礙描述。

30 fps 仍須在學校舊電腦實測，不能以光源上限代替通過證據。
