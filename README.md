# 密室逃脫遊戲

原創第一人稱 3D 恐怖密室逃脫，場景是深夜停業的「星星糖果樂園」。目前實作到 **STEP 5c：置物櫃與整合**，可取得手電筒、安裝保險絲、以紫外光找碼、輸入密碼恢復主電力，再進入第三區面對棉花糖先生的巡邏與追逐。可繞機台切斷視線，或躲進置物櫃等牠搜尋後返回巡邏。5a、5b 已由監督者通過，5c 瀏覽器未驗；被抓、存檔與聲音留待後續步驟。

## 開啟遊戲

需要 Python 3、本機 HTTP 伺服器及支援 ES module、importmap、WebGL 的桌面瀏覽器。three.js 固定使用 `0.160.0`，由 jsDelivr CDN 載入，因此需要網路。不需 `npm install`，沒有 npm 套件依賴。

Mac：在專案資料夾執行：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows PowerShell：

```powershell
py -m http.server 8000 --bind 127.0.0.1
```

Windows 若只有 `python`，可替代 `py`，需為 Python 3。瀏覽器前往 `http://127.0.0.1:8000/index.html`；按 `Ctrl+C` 停止伺服器。若埠被使用，指令及網址一起改為其他埠。不要直接點兩下 `index.html` 使用 `file://`。本機伺服器僅提供靜態檔案，沒有遊戲後端或帳號。

## 目前可玩的流程（5c）

單位為公尺；北方是 −Z。玩家從 `(0, 1.6, 6)` 面向北方開始，開場未持有手電筒，相關 HUD 隱藏，F／R、RB／LB、R1／L1 都不生效。

1. 向左前方服務台靠近，瞄準「雙光源手電筒」撿起。
2. 中央的電力室門自動開啟，手電筒 HUD 與操作提示出現；撿取當幀不自動開燈。
3. 進入電力室，探索兩張工作桌；可以撿保險絲及電池。
4. 走到東牆電箱前瞄準，按 E／A／✕ 安裝保險絲；未持有時顯示「缺少保險絲」。安裝後顯示「備援控制已接通」，只亮低亮度發光指示燈，主燈仍維持停電底光。
5. 依維修便條提示，開啟手電筒並切換紫外光，照向電箱北側的東牆墨跡；一般光不顯示文字。
6. 瞄準密碼鎖，未安裝保險絲時只顯示「控制器未通電」。安裝後按 E／A／✕ 開啟 3×4 按鍵面板；數字最多四位，刪除、確認與返回均可使用鍵鼠或手把。
7. 錯碼顯示「密碼錯誤，請重試」、清空輸入，不消耗物品、不恢復供電、不開門；可直接重試。正確碼關閉面板、開啟生產線門，兩房間主燈在 0.6 秒內從停電底光穩定亮起，沒有反覆閃爍。重複互動只回饋「主電力已恢復」，不重播。
8. 沿東側向北走到生產線門，穿過平台進入糖果生產線。首次進區啟動棉花糖先生，沿固定路線巡邏；被前方視線發現時會低頭抬臂、加快腳步。繞機台切斷視線後牠只追最後看見的位置，搜尋後返回巡邏。接觸時只顯示短暫的「衣角被扯住了。」，仍能自行離開。機台、櫃體與怪物身體不能穿過；正面瞄準櫃門按 E／A／✕ 可躲藏，再按一次出櫃。成功進櫃即甩掉追逐，從窺視縫觀察牠搜尋後離開。東側下一區門保持關閉，沒有生產線解題操作或整章結局。

|---|---|
| 大廳 | X：−5～5、Z：0～8，高 3.5 m |

門洞淨寬 1.8 m、高 2.6 m。門開關從關卡狀態推導：大廳門看手電筒取得紀錄，生產線門看該謎題的供電狀態；正確碼只改動對應謎題，不改其他門的條件。平台末端已接通第三區；第三區東門引用未解的 `production.sequence`，預留給後續步驟。

舊示範代幣、隔板及「星光在此」已從正式遊戲移除。正式 `CLUES` 由線索的 `puzzleId` 查找唯一謎題資料產生「檢修碼」文字；純密碼判定也取同一份資料，且未安裝保險絲時一律拒絕。`validatePuzzleCode` 只判定；`submitPuzzleCode` 另檢查已安裝、正確設備、已開面板與未暫停，才更新供電狀態。

## 互動與手電筒規則

中央射線命中物品 AABB 才算瞄準；距離為眼睛到首次命中表面，包含恰好 2 m。只有能撿時出現 E／A／✕ 提示。牆、家具、關門、地板與天花板都參與遮擋；同距離障礙物算擋住。物品與設備共用 `selectInteractionTarget`，只選最近可命中的目標；設備自己的 AABB 不會誤擋自身互動，其他設備仍可遮擋。模型與判定共用相同 AABB，每個物品各軸至少 0.25 m。撿起後記入 `{ itemIds: [] }` 並移除模型；沒有背包選單，重新整理會重置進度。

取得手電筒後起始為 100%、關閉、一般光。開啟時每秒減少 0.2 個百分點，兩模式相同；電池補 25，最多 100%，溢出捨棄。零電量自動關閉且不能開啟，補電不自動開燈。關閉時可切模式。按鍵只認按下邊緣；開始／繼續當幀不執行裝備動作、不耗電；暫停與失焦不耗電也不保留待執行按鍵。

紫外光可見性仍由 logic 判斷：開啟、有電、UV 模式、文字中心在半角 25°、8 m 內（含邊界）、玩家位於正面且中間無遮擋。SpotLight 共用角度及距離，不開陰影，接受光照可能穿牆的限制，隱藏字仍受 logic 遮擋限制。

4a 加入中央射線最近表面的近距光強補償：距離小於 1 m 時，以距離平方乘原強度 35；1 m 外維持 35。這只影響照明，不改電量或 UV 判斷。電量列移除 `<meter>` 內重複百分比，旁邊只保留一個可見百分比；原生 meter 保留標籤與數值語意。

## 關卡資料範本與分工

- `src/logic/areas/lobby.js`、`power-room.js`、`production.js`：各區的純資料，包含區域範圍、高度、AABB 方塊、門、物品、設備、預留謎題、線索、光源與標示；第三區另有導航與怪物資料。
- `src/logic/world.js`：彙整與驗證 ID／引用／AABB／物品尺寸，導出清單與動態幾何。
- `level.js`、`items.js`、`clues.js`：導出入口，不另複製資料。地板及天花板由區域範圍與高度產生；門檻與平台的額外表面由 `extraSurfaces` 定義。
- `src/logic/chapter.js`：初始化與純狀態更新。持有及門開關由取得紀錄／謎題狀態推導，不儲存第二份布林值。
- `src/game/world-view.js`：依相同資料建模型、標示與燈，依同一個門規則顯示／隱藏。
- `tests/fixtures/demo-room.js`：舊示範資料原樣保存，僅供回歸；正式程式不得匯入。

每個區域使用具有區域前綴的唯一 ID。物品、方塊使用完整 `minX/maxX/minY/maxY/minZ/maxZ`；門與設備用 `bounds` 包住同樣欄位，幾何由此導出。門條件與目的地的範例：

```js
{
  id: 'lobby.power-door',
  bounds: { minX: -0.9, maxX: 0.9, minY: 0, maxY: 2.6, minZ: -0.2, maxZ: 0 },
  openWhen: { type: 'hasItem', itemId: 'lobby.flashlight' },
  destination: { type: 'area', areaId: 'power-room' }
}
```

`puzzleSolved` 條件以 `puzzleId` 引用謎題。`destination.type === 'reserved'` 明確表示未實作區域，允許沒有對應區域資料；其他區域引用必須有效。

後續新增 `areas/新區域.js`，沿用上述欄位並登記於 `WORLD.areas`；共享牆／門只定義一次，接上既有門洞與地板，最後跑資料、通行與互動測試。不要在 game 再寫另一份座標或條件。

運行時一律呼叫 `getGeometry(state)`：`collisionBoxes` 是靜態實體與關門，`occluderBoxes` 另包含地板、天花板和門楣。門楣以 `blocksMovement: false` 標示，只擋視線；這配合目前固定高度的水平圓柱碰撞。開門後兩份清單同時移除同一門 AABB。單獨的 `LEVEL_BOXES` 是靜態資料，不可當成完整運行時門狀態。

## R006 4c 驗收與介面

面板狀態在 `src/logic/keypad.js`：`mode`、`deviceId`、`buffer`、`selectedIndex`、`message`。面板開啟、返回、提交的當幀不執行場景動作；開啟期間凍結移動、轉頭、場景互動、手電筒動作與耗電。十字鍵只認按下邊緣，邊界不循環。每次重開清空舊輸入；暫停、失焦或拔除使用中的手把則保留輸入，回來不重播按鍵。Start／Options 優先暫停，不提交。

鍵鼠開啟時以 `keypad` 原因釋放 Pointer Lock，不觸發暫停；Esc 優先返回。返回後依 HUD 提示實際點一下場景重新鎖定；失敗會顯示既有重試提示。面板中暫停後點「繼續」直接回面板，不要求鎖定；純手把從開始到平台都不要求 Pointer Lock。

供電進度由 logic 的 `restoreElapsed`／`powerProgress` 推導，0.6 秒到穩定亮度，暫停時停止；game 只套用相同進度到既有光源，不新增真實光源。正確碼當幀生產線門的模型、碰撞與視線遮擋一起解除。

自動測試證據：紅燈 93 通過、13 失敗（新增 12 項及 1 項獲准遷移）；綠燈 106/106。依監督者 R006-4c-d2 裁定，只把 `power-room.test.js` 第 76 行改為 `keypad`、第 77 行改為空初始訊息；未通電及 `restored === false` 的斷言不變，實作 commit 不改任何測試。

另外以 Node 事件、DOM 與 three.js 替身載入實際 `main.js`，核對路線、Pointer Lock 開關／失敗、DOM 點擊、Esc、失焦保留及假 Xbox／PS 面板操作。這不代表瀏覽器、WebGL、實體手把或效能已通過。

## R008 6c 瀏覽器存檔與開始選單（瀏覽器未驗）

存檔只使用 `star-candy-park.chapter-1.save`，版本 1。只保存必要進度及存檔點 ID，範例如下；不包含即時位置、怪物、介面、輸入、計時器、設定、密碼或尚未實作的生產線謎題進度。

```json
{
  "version": 1,
  "chapterId": "chapter-1",
  "checkpointId": "production.checkpoint",
  "itemIds": ["lobby.flashlight", "power.fuse"],
  "puzzles": {"power.main": {"installedItemId": "power.fuse", "restored": true}},
  "flashlight": {"charge": 82.5, "mode": "normal"}
}
```

格式嚴格檢查版本、欄位、型別、已知且不重複的物品 ID、電量 0～100、模式及前置條件；恢復供電必須有已取得並安裝的保險絲，生產線存檔點必須已供電。壞 JSON、不支援版本、未知 ID 或矛盾資料會拒絕載入，開始選單顯示原因，**不刪除、不自動覆寫**。讀取失敗同樣保護舊檔；只有玩家選「重新開始」並確認才允許取代該 key。沒有格式猜測或舊版遷移。

遊戲經注入的 `{getItem,setItem,removeItem}` 存取儲存，logic 不碰 `window.localStorage`。每次先完成驗證與序列化，再單次 `setItem`；不先刪檔，也不呼叫 `clear()`。寫入失敗時舊檔保留、遊戲可繼續，HUD 與開始選單顯示「尚未儲存」；待存進度保留於本頁，可在後續補寫重試。

寫入時機：新遊戲確認、首次啟用存檔點、取得物品、安裝、解題成功、模式切換及死亡回復立即寫入；單純耗電有變更才寫，距上次寫入至少 5 秒。暫停、背景與 `pagehide` 補寫；同一份已成功存妥的資料不重複寫入。平常只比對必要欄位，不逐幀序列化或存取 localStorage。

有效存檔預選「繼續」；無效或無存檔時停在「重新開始」，確認畫面預選取消。鍵鼠可點擊或用方向鍵、Enter、Esc；Xbox／PS 用十字鍵、A／✕、B／○，只認按下邊緣，長按不連續確認。繼續先以 6a 規則重建安全位置及怪物，再由當次操作開始遊戲；不回到櫃內、半套密碼鎖或被抓瞬間，也不開啟手電筒。鍵鼠依既有 Pointer Lock 開始／重試流程，手把不需要鎖定。

同頁重新開始：先暫停，點「返回開始選單」；手把在暫停畫面按 B／○。再選重新開始並確認。取消保留現有章節與舊檔；選單的「返回暫停畫面」可回原遊戲。重新開始只換章節 key；物品模型保留並依背包切換可見性，不重建或逐次 dispose，因此手電筒、電池與保險絲會重新出現。

監督者可用的選擇器：

| 用途 | 選擇器 |
|---|---|
| 開始選單／訊息 | `#start-menu`／`#start-message` |
| 繼續／重新開始 | `#start-continue`／`#start-new` |
| 確認重新開始／取消 | `#start-confirm`／`#start-cancel` |
| 返回暫停畫面／從暫停開選單 | `#start-return`／`#start-open` |
| 儲存提示 | 遊戲 `#save-status`；選單 `#start-save-status` |
| 已選取按鈕 | `#start-menu button.selected` |

測壞存檔：先在開發者工具複製保存原 key 的字串，再執行以下指令並重新載入。應停在選單、繼續不可用且說明 JSON 損壞；取消重新開始、等待或離頁均不得改寫此字串，確認重新開始後才取代。恢復原值時使用先前留存的字串。

```js
localStorage.setItem('star-candy-park.chapter-1.save', '{broken');
location.reload();
```
