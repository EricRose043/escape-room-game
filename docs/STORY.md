# 失落玩具工廠｜第一章劇情與線索設計

## 劇情主軸

玩家就是主角。多年後，主角收到匿名訊息，得知封廠前夜的夜班維修紀錄還留在工廠辦公室；訊息特別警告：「無論如何，別重啟主電源。」主角為查明工廠突然封閉的真相而進廠，入口隨即鎖死。原本的調查變成逃生。

本章回答兩件事：主角為什麼被困在工廠，以及復電後為什麼遭到玩偶追逐。故事仍保留三個後續謎團：玩偶為何在停電時離開展示台、匿名訊息是誰寄來、公司為何只用「設備故障」解釋封廠。

### 角色

- **主角／玩家：** 沒有預設姓名；因匿名訊息尋找夜班維修紀錄，進廠後必須找出路。
- **藍色展示玩偶：** 曾是公司的招牌迎賓玩具。封廠前夜後不再留在展示台，會巡邏、追逐和搜尋；失去玩家視線後會回到巡邏，不會全程黏著玩家。
- **匿名寄件者／夜班維修員：** 不直接登場。辦公室和控制室紀錄顯示，維修員發現監視畫面與門禁紀錄不一致，也警告過主電源會接通展示區備援線路。寄件者身分刻意保留。

## 解謎流程與密碼推導

### 目前已有的密碼

- **控制室 4726：** 玩家用紫外光照出牆上的檢修碼，安裝保險絲後輸入，恢復主電力。
- **裝配線 3142：** 玩家在控制器附近看到月台檢修碼，解鎖貨運門。

### R1 顏色序列謎題

四個按鈕的正確順序是 **紅 → 黃 → 綠 → 藍**。按對但未完成回報 `progress`；全對回報 `solved`；按錯回報 `wrong` 並帶 `alarm: true`，由主程式接上怪物警報。已解開後不能再被按成未解。此序列同時成為 R2 最終密碼的排序線索。純 logic 與單元測試已完成，場景按鈕、按錯時實際引怪與完成後場景回饋待主程式接入。

### R2 出口密碼：2413

三條線索分別放在裝配線、追逐走廊和出口控制板，玩家不能只靠猜測：

1. **裝配線（`production.color-clue`）：** 復位燈序為紅、黃、綠、藍。它必須和 R1 謎題的正式答案一致。
2. **追逐走廊（`corridor.color-key`）：** 維修卡給出代碼對照：紅＝3、黃＝1、綠＝4、藍＝2。
3. **出口控制板（`exit.reverse-clue`）：** 指示「將復位燈序反向輸入」。

因此輸入順序是 **藍 → 綠 → 黃 → 紅**，代入對照後得到 **2 → 4 → 1 → 3**，出口碼為 **2413**。`deriveExitCode()` 從三筆線索資料計算密碼，`exit.final` 直接引用這個結果，避免文件答案和驗證答案各存一份而走樣。logic 與出口房間資料已完成；提示擺放、收集狀態和實際密碼面板仍待 Eric 接入。

## 結局與首尾伏筆

列車通過封鎖大門，主角逃出工廠。控制室紀錄證實復電接通展示區備援線路，解釋玩偶為何在復電後追人；但備援監視器拍到玩偶在停電時已離開展示台，原因仍未知。

玩家以為已安全時，尾端空車廂的斷電廣播重播開場的舊廣告詞：「最好的朋友，陪你直到回家。」隨後車門像是從裡面扣上。開場的溫暖標語因此變成威脅，也帶出下一個懸念：玩偶是否已跟著主角上車？

## 可實玩的驗收步驟

1. 看完或跳過開場，確認廣告標語可讀，且辦公室、控制室和道具描述與實際場景一致。
2. 取得地圖與員工卡；確認官方「設備故障」說法與監視紀錄的矛盾能被玩家發現。
3. 進控制室讀取 4726，裝保險絲並復電；確認提示交代復電的必要性和備援線路風險。
4. 在裝配線躲避玩偶並輸入 3142；R1 場景接入後按紅、黃、綠、藍確認完成，故意按錯一次確認警報只觸發一次並可重新開始序列。
5. 走過追逐走廊，確認維修卡清楚列出四色數字對照，並觀察身後門的關閉。
6. R2 接入後確認出口三條線索都可在遊戲中找到，玩家能唯一推出 2413；錯碼不開門、可重試，正確碼開門後可啟動並登上列車。
7. 到結尾確認顯示遊玩時間、重新開始按鈕可用鍵鼠與 Xbox／PS 手把操作，並且開場標語重現、空車廂門扣上的新懸念出現。
8. 記錄實際 commit、瀏覽器版本、電腦與手把型號、預期及實際結果；有缺陷就附重現步驟交 shuoen88 登錄。不得將尚未接入的第 4、5 區標成通過。
