# 開場卡住或無法略過（2026-11-05）

## 同學的開啟方式

1. 到GitHub的Code → Download ZIP下載最新版，完整解壓後再操作。
2. Windows需Python 3，執行遊戲資料夾中的`Play-EscapeRoom.cmd`。不要直接雙擊`index.html`，也不要在ZIP預覽視窗裡執行。
3. 啟動器會開啟該台電腦的`http://127.0.0.1:8778/index.html`。這是每台電腦自己的網址，不能把你的127.0.0.1連結當作朋友可連入的公開遊戲網址。
4. 若使用的是已部署的遊戲網頁，重新載入；下載GitHub原始碼則使用啟動器。GitHub專案公開不等於已部署可直接玩的網站。

Mac／Linux在啟動檔所在資料夾執行`python3 play_escape_room.py`。同日新版啟動器已支援自動接替經驗證的舊遊戲服務。若仍指出8778無法接替，代表是陌生服務或無法驗證的舊服務，需先關閉原服務；不要忽略錯誤後繼續玩舊頁面。詳見[啟動器更新](LAUNCHER_UPDATES.md)。

## 新版會顯示什麼

- 正常：滑鼠點「跳過劇情」或按Enter／Space／Esc，隨即略過。若場景尚未準備好，顯示「正在準備遊戲」，首幀成功繪製後自動進入開始選單。
- 直接開HTML：顯示「請使用遊戲啟動器」，提示完整解壓及`Play-EscapeRoom.cmd`。
- 瀏覽器不支援import map：顯示需要更新桌面瀏覽器。
- 模組下載／匯入失敗：顯示「遊戲程式載入失敗」，保留錯誤資訊和重新載入按鈕。
- WebGL初始化失敗：顯示「無法啟動3D圖形」，提示檢查瀏覽器、圖形支援或換電腦。
- 前景等待30秒仍無首幀：顯示「遊戲載入較久」，可以繼續等待或重新載入。後續真的準備完成時仍可恢復，不把慢載入當成永久錯誤；背景分頁等待不計入這30秒。

仍然失敗時，展開畫面的「錯誤資訊」，複製版本、開啟方式與原因提供給製作者。重新載入不刪遊戲進度，不需要先清除localStorage或瀏覽器所有資料。

## 修正與驗證界線

舊版的略過事件綁在依賴67個ESM的`main.js`，模組未成功載入時，開場只剩CSS時間線，按鈕與換段沒有初始化。本次將開場與診斷控制直接放在HTML的獨立普通script，放在所有ESM入口之前，不依賴Three.js、import map或外部JavaScript。`main.js`在首幀成功後通知控制器就緒，鍵盤略過會消耗事件，避免同一Enter穿透選單。版本雜湊亦涵蓋獨立開場script。

新增8項回歸曾全紅，實作後288／288 Node測試通過。真HTML／原生Canvas／Three.js免GPU替身檢查：模組尚未執行即可點擊略過、正常首幀解除載入面板；真main的Renderer故意拋出WebGL錯誤時，畫面留下3D錯誤資訊。未假裝已重現同學的電腦環境；目前同學的實際開啟方式與錯誤原因仍未知。這些自動檢查不代表Chrome GPU或實體手把實測。
